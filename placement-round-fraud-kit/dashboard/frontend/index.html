About this system

"Risk" means pattern-consistency with an eleven-model unsupervised anomaly ensemble, not a verified fraud outcome — this dataset has no ground-truth fraud label, and there is deliberately no automatic block tier.

The ensemble — Isolation Forest, LOF, One-Class SVM, Elliptic Envelope, DBSCAN, HDBSCAN, K-Means, GMM, Autoencoder, VAE and an LSTM Autoencoder — is combined by percentile aggregation into a single score in (0,1). The two review tiers are the 99th percentile (priority) and 95th percentile (standard) of that score. A cost-optimal blocking threshold requires counting false negatives, which requires knowing which unflagged transactions are fraud — unknowable without a label.

This feature set is built from population-level statistics (global device / IP / merchant / account frequency counts, a top-5% amount flag, a location frequency encoding), with no per-account history or novelty flags — it can ask "is this unusual in the population" but not "is this unusual for this specific customer". Account takeover is only partially detectable here.

The dataset is also far smaller than a production deployment would see (2,512 transactions, 495 accounts, 6.88/day), and the 5% contamination rate used to tune the detectors is a documented assumption, not a measured fraud rate. Before production use: validate against investigator-labelled cases, rebuild the frequency features as prior-only running counters, and re-tune thresholds against the bank's real cost-of-fraud figures.
